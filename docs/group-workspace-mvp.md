# 微信群工作空间与存量会话（首版设计）

## 范围

首版只向微信 iLink 群开放**工作空间**。群成员可在群里新建、列出、选择、继续本群创建的会话，并查看会话状态。工作空间中已有的个人会话不进入群目录，也不能由群消息引用。群成员都可以提交一整组问题答案；群内工具批准、拒绝仅由已完成微信绑定的工作空间持有人操作。普通群成员不需要绑定微信与 W3。

开放工作空间意味着群任务可在宿主允许的范围内访问该目录文件；配置页保存前展示这个含义。首版群内查看能力是会话列表和状态摘要，尚无逐条消息历史命令。

## 可信边界与身份

1. 持有人是开放操作时本机当前验证通过的 W3 用户。群授权记录固定其 W3 主体、工作空间、已观察的机器人账号与群范围、账号代次、授权版本和状态。`NLC_CHANNEL_WORKSPACE_GRANTS_FILE` 的 `users` 只决定个人创建资格，不授予群开放资格。
2. 群消息必须由 iLink 入站同时提供 `group_id` 和实际发送者 `from_user_id`。Adapter 从可信入站构造 `weixin-group` 共享范围和群回复目的地，L2 校验二者一致；管理页只能选择已经观察到的群，不能自报群 ID。每条可信入站仅证明本次发送者在该群发言，不代表存在完整成员名册。群内动作以本次消息作为成员证据。
3. 普通群成员的微信 ID 仅用于区分请求、审计和答题，不当作 W3 用户。L2 校验群授权和群会话来源，再以授权持有人的 W3 主体调用 L3/Python 的现有资源接口；L3/Python 仍验证本机当前 W3 登录和资源归属。宿主侧没有独立获取微信群成员名册，也不独立复验每个群发送者；群身份与授权判定的信任边界在 Java Adapter/L2。宿主切换 W3 登录后，持有人证明失效，群后端操作随之失败。
4. 持有人在本机 W3 登录下申请一次性、五分钟有效的绑定码，并从本人微信向同一个机器人**私聊**发送 `/bind 绑定码`。服务端将当前 W3 主体、机器人账号及代次、实际微信发送者固定在持久绑定中；群内 `/bind` 不受理。群里 `/approve`、`/reject` 需在受理和派发时复验该绑定。撤销或换绑阻断尚未派发的审批。
5. 工作空间授权撤销后，L2 拒绝后续列表、输入、应答、审批和群投递；重新开放产生新授权，不继承旧群会话。会话创建前持久固定 `grantRef`、来源群、实际微信发送者及群回复目的地。已有个人会话没有群来源，不能通过工作空间授权继承。

## 操作与接口复用

| 操作 | 首版权限 |
| --- | --- |
| 开放或撤销群工作空间 | 本机登录的工作空间持有人 |
| 新建、列出、选择、继续或恢复本群会话，查看状态 | 当前发出可信群消息的群成员；仅 `INTERRUPTED` 会话可恢复 |
| 选择问题选项或提交整组答案 | 当前发出可信群消息的群成员；同一交互以既有修订号/CAS 保证只生效一次 |
| 批准或拒绝工具请求 | 工作空间持有人，且群内微信发送者已与其 W3 身份绑定 |

管理接口由 Python 本机已认证路由转发至 Java：群候选、群工作空间授权列表/新增/撤销，微信绑定挑战/列表/撤销，旧会话候选/登记。Electron 暴露窄 IPC，桌面端在 Channel 权限页复用现有授权入口。

群消息沿用现有命令解释、会话创建、导航、后端派发、交互领取和收件投递。群操作额外写入授权与发送者审计；重放、后台派发和投递重新检查当前授权。问答沿用 `interactionRef`、`expectedRevision` 和一次性响应领取。审批权按交互类型判断，不能从选项文本推断。回复目的地固定为该群，个人目的地不能改成群目的地。

中断恢复使用当前已选会话的 `/resume`，沿用会话访问授权与群来源限制。L3 以固定原请求键调用宿主现有恢复逻辑；宿主在调用前持久记录请求，网络结果不明时仅查询原键，不换键重试。原 Channel 输入的任务及事件关联保持原键，恢复后继续沿原投递路径回群。

## 存量个人会话发现

Channel 启动时的目录只含已登记资源，因此旧 CoWork 会话不会自动出现在 Channel 会话列表。本机管理页现在从 CoWork 持久化会话状态读取候选，分页展示，并让当前 W3 用户明确选择登记。候选的历史 `user_id` 或 `surrogate_id` 只是筛选线索；登记时再次验证当前 W3 登录、记录仍存在及当前目录归属。无归属线索、不匹配当前用户或已经属于他人的记录不进入候选；重复登记幂等。登记后仍是**个人**会话，不进入任何群目录。

旧记录的 `user_id` 来源于历史客户端信息，缺少独立创建时签名。因而此流程是本机登录者主动核认，不是对历史归属的强密码学证明。需要更强证明时须由历史创建端提供可验证凭据。

## 验证与待现场验收

夹具覆盖群字段解析与回群目标、跨群/个人会话拒绝、两位成员共享新会话、并发答题只接受一次、持有人微信绑定后审批、解绑与授权撤销、迟到投递、旧会话分页及账号切换。实际目标机器人尚未收到过真实群消息，真实群字段、群成员资格语义和群回复能否成功仍需目标微信群现场验收。腾讯 iLink 协议将 `group_id` 列为可选字段，但这不能单独证明当前机器人账号已有群聊能力：[协议消息模型](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol.md#message-model)。
